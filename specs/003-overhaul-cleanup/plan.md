# Implementation Plan: Overhaul Release Cleanup

**Branch**: `003-overhaul-cleanup` | **Date**: 2026-03-17 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/003-overhaul-cleanup/spec.md`

## Summary

Four-story overhaul covering test isolation from the dev database (P1), optional width/length
fields on dimension segments (P2), Node 22 LTS upgrade and Dockerfile hardening (P3), and
raising test coverage to the project's existing 80% gate (P4).

Technical approach:
- **Test isolation**: Inject test DB env vars via Jest `setupFiles` so `AppDataSource` at
  module-load time connects to the test DB; remove `AppDataSource.initialize()` from
  `dbSetup.ts`.
- **Segment dimensions**: Add nullable `decimal(10,4)` `width` and `length` columns to
  `DimensionSegment` entity + new TypeORM migration; update all DTOs, service mappers, and
  frontend types/forms/display.
- **Node upgrade**: Change `FROM node:20-alpine` → `FROM node:22-alpine` in both Dockerfiles;
  add `RUN chown -R node:node /app` + `USER node` to backend production stage.
- **Coverage**: Add `SettingsService.test.ts` (backend) and six frontend service-client test
  files to reach ≥ 80% line/branch coverage.

## Technical Context

**Language/Version**: TypeScript 5.3.3 (strict mode) — frontend and backend

**Target Platform**: Docker containers (production); Node 22 LTS host (development)
**Project Type**: Web application (React frontend + Express/TypeORM backend)
**Performance Goals**: All save/update actions complete within 2 seconds (SC-004)
**Constraints**: Test suite must complete in under 60 seconds; 80% line and branch coverage
**Scale/Scope**: Single-developer local app; 2-container Docker stack
